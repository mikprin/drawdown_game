# Архитектура

## Стек

| Что | Версия | Зачем |
|---|---|---|
| TypeScript | 7.0 (нативный `tsc`) | Строгий режим, `noUnused*` |
| Vite | 8.3 | Dev-сервер и сборка (`base: './'`, поэтому `dist/` можно открыть с любого пути) |
| PixiJS | 8.22 | Сцена на WebGL. Единственная зависимость в рантайме |
| Vitest | 4.1 | Тесты симуляции |

Шрифты подключаются с Google Fonts: Barlow Condensed для заголовков, IBM Plex Mono для цифр и текста. Без сети браузер подставит системные.

## Структура

## Принципы

1. **Симуляция чистая.** `src/game` не знает про DOM и Pixi. Всё состояние — один JSON-сериализуемый объект `GameState`.
2. **Детерминизм.** Состояние генератора случайных чисел лежит в самом стейте, поэтому одинаковый seed и одинаковые действия дают одинаковый результат (это проверяется тестом). Всё случайное в мире (успех лида, его размер, шум оценок) бросается заранее, при генерации карты.
3. **Действия с dry-run.** Каждое действие имеет вид `action(s, …args, dry = false): Result`, где `Result = { ok: true, cost } | { ok: false, reason }`. Интерфейс вызывает действие с `dry = true`, чтобы показать цену, заблокировать кнопку и вывести причину во всплывающей подсказке. Логика проверки при этом одна.
4. **Потоки — производные.** `s.flows` (суточные потоки последнего шага) пересчитывается каждый шаг и не сохраняется. Интерфейс и рендер читают только его.
5. **Рендер отделён от арта.** Сцена берёт текстуры из `SpriteBank`. Любую запекающую функцию в `sprites.ts` можно заменить загрузкой PNG, сцену трогать не придётся.

## Шаг симуляции (`sim.ts → step`)

```
updateMarket   режим, база, шум, затухание давления продаж
advanceJobs    бурение, лифт, ГРП, перевод под закачку, ремонт, обустройство, сейсмика, разведочная скважина
computeFlows   потенциалы скважин → общий штуцер или SCADA → маршрут воды → продажи → газ → затраты
applyFlows     резервуары, деньги, накопленная добыча, давление продаж, статистика
updateFields   flood и floodMaturity по компенсации отбора
updateWear     затухание ГРП, износ, отказы, бригада обслуживания
               на границе суток: история (720 дней) и проверка целей
```

## Игровой цикл (`main.ts`)

- Тикер Pixi копит реальное время × скорость и выполняет `step(s, 0.1)` нужное число раз (не больше 300 за кадр). Затем `stage.frame()` анимирует сцену.
- Раз в 200 мс вызывается `refresh()`: синхронизация сцены (`stage.sync`) и обновление всех панелей.
- `ctx.act(fn)` применяет действие и сразу вызывает `refresh()`.
- Когда вкладка скрыта, браузер останавливает кадры. При возврате пропущенное время досчитывается как офлайн.

## Рендер

### Изометрия и процедурные спрайты

- Проекция 2:1: `iso(gx, gy, z) = ((gx − gy)·32, (gx + gy)·16 − z)`. Тайл 64×32, по вертикали 36 px на клетку.
- Примитивы в `paint.ts`:

  | Примитив | Что рисует |
  |---|---|
  | `box` | Изометрический короб, освещён слева |
  | `cylV` | Вертикальный цилиндр с градиентом |
  | `cylH` | Горизонтальный сосуд, собранный из проекций сечений по алгоритму художника |
  | `line3` | Трубы и фермы |
  | `disc` | Проекция окружности (колёса, штурвалы) |
  | `shadow` | Тень на земле |

- `grime()` проходит по пикселям: пятна грязи (fbm), ржавые пятна и вертикальные ржавые подтёки (шум, растянутый по вертикали). Затрагивает только непрозрачные пиксели.
- Спрайты запекаются в 2× для чёткости при зуме. `bakeCropped()` обрезает прозрачные поля и пересчитывает точку привязки (anchor = точка касания земли).
- **Земля** — одна текстура мира 60×60 клеток: тайлящиеся шумовые паттерны (грунт, гравий, дорога), пятна, площадки кустов, обвалование резервуаров, пруд, радиальное затемнение к краям. Перезапекается только при смене набора кустов, появлении пруда или трубопровода.

### Слои `SiteView` (снизу вверх)

| Слой | Что на нём |
|---|---|
| ground | Запечённая земля |
| lines | Пока пустой (см. roadmap) |
| flow | Выкидные линии и точки потока, трубопровод; перерисовываются каждый кадр |
| objects | Все объекты, `sortableChildren`, `zIndex = (gx + gy)·10` |
| gauges | Шкалы заполнения резервуаров |
| fx | Аддитивный слой: пламя, маяки |
| overlay | Кольцо выбора скважины |
| labels | Подписи кустов |

- `sync(s)` (5 Гц) пересоздаёт объекты по ключам: набор объектов хаба, вид каждой скважины, подписи.
- `update(s, dt)` (каждый кадр) рисует балансир качалки (балансир, головка, канатная подвеска, шатуны, кривошип), движение грузовиков, пламя и дым, маяки, выделение.
- Клик по скважине обрабатывает Pixi (`pointertap`). Отличить перетаскивание от клика помогает `isDragGesture` из `Stage`.

### `MapView`

- Рельеф запекается один раз: цвет по типу рельефа, отмывка по высоте, горизонтали.
- Туман — спрайт на каждый неразведанный блок плюс янтарная подложка с региональной подсказкой.
- Тепловая карта (Graphics), маркеры, подписи (Pixi Text) перестраиваются только при смене ключа: разведка, бурение, месторождения.
- Анимации: развёртка сейсмики, мигающая буровая с кольцом прогресса, курсор и выбор.
- Карта вписывается в экран; панорамы и зума на карте нет.

### Как заменить арт

Каждая функция в `sprites.ts` возвращает `Baked { texture, ax, ay }`. Чтобы подставить нарисованный спрайт, загрузите PNG через `Assets.load` и верните тот же интерфейс с anchor в точке касания земли. Координаты слотов и объектов задаются в `layout.ts`.

## Интерфейс

- Обычный DOM без фреймворка. `h(tag, attrs, ...children)` создаёт элементы, `setText` пишет в DOM только при изменении.
- Панели строят разметку один раз, а потом обновляют значения. Списки (скважины, вкладки, открытия) перестраиваются только при смене ключа — например, набора id, статусов и лифтов.
- `ActionButton(label, check, run, { hint, labelFn, cls })` сам показывает цену или причину блокировки.
- `Ctx` хранит текущий стейт, выбор в UI (вкладка, месторождение, скважина, клетка, скорость) и методы `act`, `select*`, `setView`, `setSpeed`, `save`, `newGame`.
- Вёрстка — CSS grid: верхняя полоса, левая панель, вид, низ, правая панель. На ширине до 860 px всё складывается в колонку.

## Сохранения

- Ключ в localStorage — `drawdown.save`, версия `SAVE_VERSION = 1`. Если версия не совпадает, начинается новая игра: миграций пока нет.
- `flows` не сохраняется. `savedAt` нужен для офлайн-досчёта; окно «While you were away» показывается, если прошло 5 суток и больше.
- «New game» ставит флаг `resetting`, очищает сохранение и перезагружает страницу. Флаг нужен, чтобы `beforeunload` не сохранил старую игру поверх.

## Инструменты разработки

- **Dev-хук** (только `npm run dev`): `window.__drawdown` с полями `s` (стейт), `ctx`, `actions` и `step(days)`.
- **Бот баланса**: `npx rolldown scripts/balance.ts --file /tmp/b.mjs --platform node && node /tmp/b.mjs <seed> <days>`. Жадно играет первый слой и печатает таймлайн (подробности в [balance.md](balance.md)).
- **Тесты**: `npm test` — 12 тестов, см. [README](README.md#проверка).
- **Скриншоты и смоук-тест**: в репозиторий не входят. Использовались `playwright-core` из временной папки и закэшированный Chromium с `--use-angle=swiftshader`. Сценарий: открыть страницу, через `page.evaluate` дёрнуть `__drawdown` и сделать скриншот.

## Производительность

Замеры в мид-гейме, 11 скважин:
- `step`: около 0.1 мс;
- `refresh` всех панелей: около 0.4 мс.

Узкое место — только GPU и растеризация. Самая большая текстура — земля, примерно 3840×2300.
