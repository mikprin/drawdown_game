# Архитектура

## Стек

| Что | Версия | Зачем |
|---|---|---|
| TypeScript | 7.0 (нативный `tsc`) | Строгий режим, `noUnused*` |
| Vite | 8.3 | Dev-сервер и сборка (`base: './'`, поэтому `dist/` можно открыть с любого пути) |
| PixiJS | 8.22 | Сцена на WebGL. Единственная зависимость в рантайме |
| Vitest | 4.1 | Тесты симуляции |

Шрифты подключаются с Google Fonts: Barlow Condensed для заголовков, IBM Plex Mono для цифр и текста. У Barlow Condensed нет кириллицы, поэтому в русском интерфейсе заголовки набираются Fira Sans Extra Condensed (переключение через `html[lang='ru']` в CSS; файлы шрифта грузятся только для используемого языка). Без сети браузер подставит системные.

## Принципы

1. **Симуляция чистая.** `src/game` не знает про DOM и Pixi. Всё состояние — один JSON-сериализуемый объект `GameState`.
2. **Детерминизм.** Состояние генератора случайных чисел лежит в самом стейте, поэтому одинаковый seed и одинаковые действия дают одинаковый результат (это проверяется тестом). Всё случайное в мире (успех лида, его размер, шум оценок) бросается заранее, при генерации карты.
3. **Действия с dry-run.** Каждое действие имеет вид `action(s, …args, dry = false): Result`, где `Result = { ok: true, cost } | { ok: false, reason: Msg, cost? }`. `cost` при отказе заполнен, когда не хватает только денег, — кнопка всё равно показывает цену. Интерфейс вызывает действие с `dry = true`, чтобы показать цену, заблокировать кнопку и вывести причину в карточке-подсказке. Логика проверки при этом одна.
6. **Симуляция не хранит текст.** Журнал и причины отказа — это `Msg { key, params }`. Числа в параметрах сырые, формат задаёт шаблон (`{cost:money}`), имена лифтов и технологий передаются вложенным `Msg`. Поэтому журнал перерисовывается на любом языке, в том числе старые записи.
4. **Потоки — производные.** `s.flows` (суточные потоки последнего шага) пересчитывается каждый шаг и не сохраняется. Интерфейс и рендер читают только его.
5. **Рендер отделён от арта.** Сцена берёт текстуры из `SpriteBank`. Любую запекающую функцию в `sprites.ts` можно заменить загрузкой PNG, сцену трогать не придётся.

## Шаг симуляции (`sim.ts → step`)

```
updateMarket      режим, база, шум, затухание давления продаж
updateWeather     шторм: предупреждение, начало, конец (только когда есть карта шельфа)
advanceJobs       бурение, лифт, ГРП, перевод под закачку, ремонт, обустройство и установка платформ,
                  сейсмика и разведочные скважины на обеих картах; в шторм работы на море стоят
advancePlatforms  ликвидация платформ
computeFlows      хаб: потенциалы → общий штуцер или SCADA → вода → продажи → газ → затраты;
                  затем каждая платформа (computePlatformFlows) и итоги `flows.total`
applyFlows        резервуары, деньги, накопленная добыча, давление продаж, статистика;
                  платформы: ёмкости, налив в танкер, затраты, рейсы и продажи грузов
updateFields      flood и floodMaturity по компенсации отбора
updateWear        затухание ГРП, износ, отказы, бригада обслуживания (на море ремонт ждёт буровую)
                  на границе суток: история (720 дней, суммарные нефть и прибыль) и проверка целей
```

`s.flows` — потоки наземного хаба (как в первом слое), плюс `flows.wells` по всем скважинам, `flows.platforms[id]` по платформам и `flows.total` для верхней полосы и истории. Выручка платформы приходит рывками при продаже груза; для P&L и «прибыли в сутки» берётся её среднее за 30 суток (`Platform.revenueEma`).

## Игровой цикл (`main.ts`)

- Тикер Pixi копит реальное время × скорость и выполняет `step(s, 0.1)` нужное число раз (не больше 300 за кадр). Затем `stage.frame()` анимирует сцену.
- Раз в 200 мс вызывается `refresh()`: синхронизация сцены (`stage.sync`) и обновление всех панелей.
- `ctx.act(fn)` применяет действие и сразу вызывает `refresh()`.
- Когда вкладка скрыта, браузер останавливает кадры. При возврате пропущенное время досчитывается как офлайн.

## Рендер

### Изометрия и процедурные спрайты

- Проекция 2:1: `iso(gx, gy, z) = ((gx − gy)·32, (gx + gy)·16 − z)`. Тайл 64×32, по вертикали 36 px на клетку.
- Примитивы в `paint.ts`:

  | Примитив | Что рисует |
  |---|---|
  | `box` | Изометрический короб, освещён слева |
  | `cylV` | Вертикальный цилиндр с градиентом |
  | `cylH` | Горизонтальный сосуд, собранный из проекций сечений по алгоритму художника |
  | `line3` | Трубы и фермы |
  | `disc` | Проекция окружности (колёса, штурвалы) |
  | `shadow` | Тень на земле |

- `grime()` проходит по пикселям: пятна грязи (fbm), ржавые пятна и вертикальные ржавые подтёки (шум, растянутый по вертикали). Затрагивает только непрозрачные пиксели.
- Спрайты запекаются в 2× для чёткости при зуме. `bakeCropped()` обрезает прозрачные поля и пересчитывает точку привязки (anchor = точка касания земли).
- **Земля** — одна текстура мира 60×60 клеток: тайлящиеся шумовые паттерны (грунт, гравий, дорога), пятна, площадки кустов, обвалование резервуаров, пруд, радиальное затемнение к краям. Перезапекается только при смене набора кустов, появлении пруда или трубопровода.

### Слои `SiteView` (снизу вверх)

| Слой | Что на нём |
|---|---|
| ground | Запечённая земля |
| lines | Пока пустой (см. roadmap) |
| flow | Выкидные линии и точки потока, трубопровод; перерисовываются каждый кадр |
| objects | Все объекты, `sortableChildren`, `zIndex = (gx + gy)·10` |
| gauges | Шкалы заполнения резервуаров |
| fx | Аддитивный слой: пламя, маяки |
| overlay | Кольцо выбора скважины |
| labels | Подписи кустов |

- `sync(s)` (5 Гц) пересоздаёт объекты по ключам: набор объектов хаба, вид каждой скважины, подписи.
- `update(s, dt)` (каждый кадр) рисует балансир качалки (балансир, головка, канатная подвеска, шатуны, кривошип), движение грузовиков, пламя и дым, маяки, выделение.
- Клик по скважине обрабатывает Pixi (`pointertap`). Отличить перетаскивание от клика помогает `isDragGesture` из `Stage`.

### `MapView`

- Рельеф запекается один раз: цвет по типу рельефа, отмывка по высоте, горизонтали.
- Туман — спрайт на каждый неразведанный блок плюс янтарная подложка с региональной подсказкой.
- Тепловая карта (Graphics), маркеры, подписи (Pixi Text) перестраиваются только при смене ключа: разведка, бурение, месторождения.
- Анимации: развёртка сейсмики, мигающая буровая с кольцом прогресса, курсор и выбор.
- Карта вписывается в экран; панорамы и зума на карте нет.

### `SeaView` (шельф)

- Показывает одну выбранную платформу. Спрайты шельфа (`seaSprites.ts`) запекаются при первом заходе: большинство партий до шельфа не доходят или доходят поздно.
- Вода — два `TilingSprite` (зыбь и блики), они дрейфуют, в шторм темнеют и ускоряются. Тени, пена у опор и шланг налива рисуются в `Graphics` каждый кадр.
- Слои снизу вверх: море → суда (танкеры, буй, судно снабжения) → нижние части опор → палуба (корпус и объекты с сортировкой по глубине) → fx (пламя, маяки) → выделение и шланг → подпись.
- Палуба — отдельный контейнер. При постройке и ликвидации он смещается вниз: корпус «ползёт» по опорам. Спрайты модулей с суши ставятся на высоту палубы (`DECK_Z`); спрайты шельфа уже запечены с этой высотой.
- Раскладка палубы и судоходные полосы заданы константами в начале `sea.ts`. Буровая переезжает к скважине, над которой работает.
- Шторм поверх сцены (затемнение и дождь) рисует `Stage` в экранных координатах.

### Как заменить арт

Каждая функция в `sprites.ts` возвращает `Baked { texture, ax, ay }`. Чтобы подставить нарисованный спрайт, загрузите PNG через `Assets.load` и верните тот же интерфейс с anchor в точке касания земли. Координаты слотов и объектов задаются в `layout.ts`.

## Интерфейс

- Обычный DOM без фреймворка. `h(tag, attrs, ...children)` создаёт элементы, `setText` пишет в DOM только при изменении.
- Панели строят разметку один раз, а потом обновляют значения. Списки (скважины, вкладки, открытия) перестраиваются только при смене ключа — например, набора id, статусов и лифтов.
- `ActionButton(label, check, run, { help, labelFn, cls })` сам показывает цену; описание и причину блокировки выводит карточка-подсказка. Кнопка блокируется через `aria-disabled`, а не `disabled`: на `disabled`-элементах браузеры не всегда шлют события мыши, и подсказка бы не появилась.
- `Ctx` хранит текущий стейт, выбор в UI (вкладка, месторождение на суше, платформа, скважина, клетка, карта суша/шельф, скорость) и методы `act`, `select*`, `selectPlatform`, `setMap`, `setView`, `setSpeed`, `save`, `newGame`, `setLang`. `currentField(ctx)` — месторождение, о котором левая панель: выбранное на суше или поле выбранной платформы.
- Вкладки над сценой несут тревоги сцен, на которые игрок сейчас не смотрит: красная точка — где-то узкое место, синяя — шторм на шельфе. Вкладка «Шельф» появляется с первой платформой.

### Локализация

- Строки только в `src/i18n/en.ts` и `ru.ts`. Плейсхолдеры: `{name}` как есть, `{name:fmt}` с форматом (`money`, `bbl`, `rate`, `num`, `pct`, `pct1`, `days`, `price`, `gas`), `{name:plural:один|другие}` со знаком `#` вместо числа. В русском формы идут в порядке one|few|many (1 скважина | 2 скважины | 5 скважин) через `Intl.PluralRules`.
- Тест проверяет, что в обоих словарях у каждого ключа одинаковые плейсхолдеры и у русских plural ровно три формы.
- Единицы локализуются в `format.ts`: десятичная запятая, «тыс./млн/млрд» (числа до 10 000 пишутся целиком, иначе сокращение длиннее числа), «барр./сут», «б/с» в узких ячейках. Газ в русском интерфейсе показывается в тыс. м³ (пересчёт из mcf, симуляция по-прежнему считает в mcf).
- Язык выбирается в меню-шестерёнке и хранится отдельно от сохранения (`drawdown.lang`). По умолчанию берётся из `navigator.language`. При переключении `mountUi()` в `main.ts` пересоздаёт все DOM-панели; сцена подхватывает язык сама (подписи кустов обновляются каждый `sync`, ключ статики карты включает язык).
- Названия месторождений и скважин — имена собственные, не переводятся.

### Подсказки (глоссарий)

- `help(el, source)` вешает на элемент объяснение: либо id из глоссария (`help.<id>.t` / `help.<id>.b` в словарях), либо функцию, которая собирает карточку на лету (описание объекта, причина блокировки, «сейчас это узкое место»).
- Текстовые термины с подсказкой подчёркнуты пунктиром. Кнопки не подчёркиваются, но тоже показывают карточку.
- Одна карточка `#help` на документ (`HelpCard`): появляется через 350 мс наведения, встаёт сбоку от левой или правой панели на высоте элемента, у верхней и нижней полосы — под или над ним. Пока карточка видна, она обновляется вместе с панелями (5 Гц), так что цена и причина в ней живые.
- Вёрстка — CSS grid: верхняя полоса, левая панель, вид, низ, правая панель. На ширине до 860 px всё складывается в колонку.

## Сохранения

- Ключ в localStorage — `drawdown.save`, версия `SAVE_VERSION = 3`. `migrate()` в `save.ts` поднимает старые версии: v1 → v2 переводит записи журнала из текста в `Msg` (`log.raw`, старые записи остаются на английском); v2 → v3 добавляет пустой шельф (`shelf: null`, `platforms: []`, `weather`, `stats.cargoes`). Неизвестная версия — новая игра.
- `flows` не сохраняется. `savedAt` нужен для офлайн-досчёта; окно «While you were away» показывается, если прошло 5 суток и больше.
- «New game» ставит флаг `resetting`, очищает сохранение и перезагружает страницу. Флаг нужен, чтобы `beforeunload` не сохранил старую игру поверх.

## Инструменты разработки

- **Dev-хук** (только `npm run dev`): `window.__drawdown` с полями `s` (стейт), `ctx`, `actions` и `step(days)`.
- **Бот баланса**: `npx rolldown scripts/balance.ts --file /tmp/b.mjs --platform node && node /tmp/b.mjs <seed> <days>`. Жадно играет первый слой и печатает таймлайн (подробности в [balance.md](balance.md)).
- **Тесты**: `npm test` — 31 тест (симуляция, шельф, сохранения и миграции, i18n), см. [README](README.md#проверка).
- **Скриншоты и смоук-тест**: в репозиторий не входят. Использовались `playwright-core` из временной папки и закэшированный Chromium с `--use-angle=swiftshader`. Сценарий: открыть страницу, через `page.evaluate` дёрнуть `__drawdown` и сделать скриншот.

## Производительность

Замеры в мид-гейме, 11 скважин:
- `step`: около 0.1 мс;
- `refresh` всех панелей: около 0.4 мс.

Узкое место — только GPU и растеризация. Самая большая текстура — земля, примерно 3840×2300.
